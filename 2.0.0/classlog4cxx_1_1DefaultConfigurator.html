spi::ConfigurationStatus log4cxx::DefaultConfigurator::configure ( const spi::LoggerRepositoryPtr & repository = {})
static

Configure repository.

If the configuration file name has not been provided by a call to setConfigurationFileName(), the environment variable "LOG4CXX_CONFIGURATION" value is used, with ${varname} instances using either a system environment variable value (if found) otherwise using the helpers::Properties object provided by spi::Configurator::properties.

Example usage:
setenv LOG4CXX_CONFIGURATION="${PROGRAM_FILE_PATH.PARENT_PATH}/${PROGRAM_FILE_PATH.STEM}.xml"

If the configuration file name is not specified, the current directory is examined for a file with extension ".xml" or ".properties" with a base name "log4cxx" or "log4j".

Unless a configurator is specified using the "LOG4CXX_CONFIGURATOR_CLASS" environment variable, or by a call to setConfiguratorClass(), Log4cxx will call the spi::Configurator::isValid method on an instance of each class registered with Log4cxx whose name ends with "Configurator". The first configurator instance whose spi::Configurator::isValid method returns true is used to process the configuration file.

If a positive number has been provided by a call to setConfigurationWatchSeconds() or the environment variables "LOG4CXX_CONFIGURATION_WATCH_SECONDS" contains a positive number a background task is started that will periodically check for a change to the configuration file and apply any configuration changes found.

Call configure() passing the default repository after calling setConfigurationFileName() with a path composed of an entry in directories and an entry in filenames when the combination identifies an existing file.

Example usage:
std::vector<LogString> directories
{ LOG4CXX_STR(".")
, LOG4CXX_STR("${PROGRAM_FILE_PATH.PARENT_PATH}")
};
std::vector<LogString> filenames
{ LOG4CXX_STR("${PROGRAM_FILE_PATH.STEM}.xml")
, LOG4CXX_STR("${PROGRAM_FILE_PATH.STEM}.properties")
, LOG4CXX_STR("log4cxx.xml")
};
DefaultConfigurator::configureFromFile(directories, filenames);

Call configure() passing the default repository after calling setConfigurationFileName() with a path ...

Using the above example and an executable file named "myapp" installed in the directory "/opt/com.foo/bin", locations are checked in the following order:

  1. "./myapp.xml"
  2. "./myapp.properties"
  3. "./log4cxx.xml"
  4. "/opt/com.foo/bin/myapp.xml"
  5. "/opt/com.foo/bin/myapp.properties"
  6. "/opt/com.foo/bin/log4cxx.xml"

If a file exists but it is not able to be used to configure Log4cxx, the next file in the combinatorial set will be tried until a valid configuration file is found or all values in the combinatorial set have been tried.
